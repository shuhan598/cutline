# 错误码输出测试样例

| 文件 | HTTP 状态 | 错误码 | 中文描述 |
| --- | --- | --- | --- |
| `1012_2995_unknown_root_field.json` | 422 | `1012` / `2995` | 请求格式、字段类型或载荷标准化错误 / 请求包含未声明字段 |
| `1012_2291_unknown_nested_field.json` | 422 | `1012` / `2291` | 请求格式、字段类型或载荷标准化错误 / 请求包含未声明字段 |
| `1010_2101_empty_orders.json` | 422 | `1010` / `2101` | 后端数据不完整、格式错误或关联关系错误 / 必需数据集为空 |
| `1010_2193_invalid_number.json` | 422 | `1010` / `2193` | 后端数据不完整、格式错误或关联关系错误 / 数字字段无法解析 |
| `1011_snapshot_conversion_failed.json` | 422 | `1011` | 请求数据无法转换为算法快照 |
| `3003_duplicate_buffer.json` | 200 | `3003` | 同一物理 main 内存在重复的 Buffer 编码 |
| `3111_process_duration_missing.json` | 200 | `3111` | 机台和源产品的工艺时长缺失 |

各样例的 `message` 均含算法范围和定位信息：除混料追溯外，错误以 `切线/混料-` 开头；局部计算问题附带 `warning_key`，混料追溯问题以 `混料-机台编码` 开头。

`3003` 和 `3111` 是可隔离的局部算法错误，位于响应的 `errors[]` 中。`3111` 需在已存在切线事件的第二轮计算中触发，因此该样例执行 `CutlineService.evaluate_algorithm`；常规 HTTP 请求会先按数据完整性校验返回 `1010`。
